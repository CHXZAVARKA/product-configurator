# Пошаговый конфигуратор изделий

Отдельный клиентский проект. Первый товар: калейдоскоп «Красивое стекло». Общая основа должна позволить затем сделать конфигуратор лампы KOMPONENT L-01.

## Подтверждено пользователем

- Пошаговый выбор параметров с постоянным 3D-просмотром сбоку.
- Компактная панель текущего шага с минимумом информации.
- Исходное содержание шагов берём из действующего конфигуратора Tilda.
- Сравниваем разные варианты интерфейса до выбора реализации.
- Начинаем с интервью, затем проектируем модули и клиентский сценарий.
- Проект имеет отдельную папку и локальный Git.
- Первый сценарий рассчитан на корпоративного заказчика; опираемся на существующую логику и улучшаем её удобство.
- Завершение: передача конфигурации менеджеру, предварительный расчёт, состав заказа, 3D и ссылка на вариант.
- Сначала каталог с 3D-моделями и заглушками там, где модели нет. Полный сценарий пока только у «Авторского»; остальные изделия сейчас не реализуем.
- После выбора «Авторского» показываем собранную рекомендуемую комплектацию с предварительной ценой. Настройки доступны через шаги, меню и нажатие на детали 3D.
- Клиент и сотрудники используют общие возможности оформления: загрузку и размещение изображений, работу со слоями, белилами и лаком. Сегментация, рисование масок и карты нормалей/глубины входят в планируемое направление, их реализация ещё не выбрана.
- Сотрудник подключается при разработке нового дизайна или выбранной помощи с макетом. Обязательная ручная подготовка дизайнером каждого заказа больше не является требованием; допуск файла в производство ещё обсуждается.
- Новый товар подключает разработчик через описание шагов, правил, цен и 3D-модели.
- Единый конфигуратор предназначен и для самостоятельной работы клиента, и для работы команды. Детская версия относится к последующему этапу.

## Текущий этап

Интервью `grill-me` / `grilling`: приняты ответы двух раундов, уточнён единый инструмент для клиента и команды. [Запись интервью](docs/discovery.md) отделяет подтверждённые решения от идей транскрипции и предложений. Архитектура, технологический стек, объём первой версии и финальный интерфейс не выбраны.

После определения цели: карта решений `wayfinder` в локальном Markdown, проектирование по `codebase-design`, затем UI-прототип по `prototype`. Карта ещё не создана: её назначение и первая группа решений должны следовать из интервью.
