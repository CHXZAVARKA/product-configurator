# Стёклышки, HDR-окружение и призма

Локальный просмотр: `http://127.0.0.1:3039/`. Запуск из корня проекта:

```sh
python3 prototypes/PROTOTYPE-realism/elving/build-realtime.py
python3 prototypes/PROTOTYPE-realism/elving/preview.py
```

Самостоятельный `PROTOTYPE-realtime.html` работает и без сервера. По умолчанию включены 124 объёмных осколка, HDR-студия, сглаживание и вид через призму. Можно встряхивать, поворачивать, менять наклон, ставить физику на паузу и выбирать 24–124 осколка. После успокоения физика останавливается. Отрисовка тоже засыпает, когда выключены вращение стёкол и вращение HDRI. Картинка пользователя загружается только в браузер.

Эльвинг выключен по умолчанию, GPU не строит для него лучи. Его прежнее преломление можно включить в дополнительных настройках. Для него оставлен и отдельный CPU-контроль по `/PROTOTYPE-elving.html`.

## Откуда берётся изображение

Three MeshPhysicalMaterial рисует геометрию тех же выпуклых тел, которые участвуют в Rapier. Материал использует IOR 1,5, толщину осколка, поглощение цвета, HDR PMREM и неподвижную карту микронеровностей. Сглаживание меняет нормали, сохраняя рёбра от 40°. Осколки разделены на четыре группы по глубине: каждая следующая группа преломляет цвет предыдущих. Изображение стекла 512 × 512, внутренний захват прозрачности 384 × 384. Это растровый рендер без path tracing.

Окружение `studio_small_08_1k.hdr` уже находилось в проекте. Poly Haven, Studio Small 08, CC0; источник записан в `PROTOTYPE-optics/assets/SOURCES.md`. Панорама используется и на фоне, и для отражений с одинаковым поворотом на 360°. Кнопка «Вращать HDRI» двигает освещение независимо от тел и не будит спящую физику. «Сила света» меняет HDR-яркость и освещение. «Свечение бликов» управляет коротким bloom-фильтром ярких HDR-участков перед тоновым отображением. Самосвечения у материала нет: при нулевом свете весь кадр чёрный даже с включённым bloom. HDR-фон передаётся в PBR линейным, тоновое отображение выполняется один раз.

Призма повторяет итоговую картинку через три внутренние зеркальные плоскости из CAD. Луч зеркального канала начинается у глазка z = 208,1 мм и проходит участок z = 192…12 мм. Общая картинка стекла приближает угловую зависимость преломления.

## Физика и её ограничения

Камера берёт из CAD внутренний радиус 19 мм и номинальный диапазон z = −0,5…10 мм. Для скорости используются 32 стенки и плоская верхняя огибающая эльвинга. Его углубления не участвуют в контактах. Дополнительная коррекция удерживает все вершины осколков внутри камеры. Осколки сталкиваются как объёмные выпуклые тела, расчёт идёт с шагом 1/120 с.

Слабое устойчивое контактное дрожание останавливается после интервала низкой энергии; движение, встряхивание или новый наклон будят тела. Демпфирование и пороги сна подобраны для интерактивного просмотра. Это не измеренная модель поведения конкретной реальной насыпки. В STEP нет отдельных свободных стёкол, их контуры 4–7 вершин, размеры около 5–6 мм и толщина около 2 мм процедурные. Для 124 осколков твёрдое стекло занимает около 33% номинального объёма камеры.

Осколки внутри одной группы глубины используют общий фон преломления. Каустики и многократные взаимные отражения не считаются. Фотореализм и совпадение с конкретным изделием не подтверждены сравнением с эталонным видео.

## Проверки

```sh
node prototypes/PROTOTYPE-realism/elving/evidence/chips-physics-check.mjs
# Сервер 3039 должен работать для этой проверки.
node prototypes/PROTOTYPE-realism/elving/evidence/chips-browser.mjs
node prototypes/PROTOTYPE-realism/elving/evidence/hdri-browser.mjs
# Отдельный контроль материала с временным локальным сервером.
node prototypes/PROTOTYPE-realism/elving/evidence/pbr-material-check.mjs
```

На Apple M1 для текущих 124 осколков физика дала p95 6,75 мс активного кадра в Node. Браузерный проход с физикой, PBR и зеркалами после прогрева дал p95 7,4 мс по 40 кадрам с ожиданием GPU. Эльвинг был отключён. Холодный короткий замер дал p95 27 мс. Эти значения описывают проверенный сценарий и оборудование, не гарантируют скорость на всех устройствах.

`chips-physics.json` содержит проверки выпуклости, начального разделения, движения, переворотов, сна, пробуждения, удержания всех вершин в камере и непрерывного поворота на 144 Гц. `chips-browser.json` подтверждает живое пересыпание, PBR-сглаживание, HDR, отсутствие CAD-проходов по умолчанию, опциональный эльвинг, загрузку изображения и мобильную раскладку. Скриншоты находятся рядом с отчётом. Браузерные проверки закрывают свой временный Chrome.

## Контрольный CPU-рендер

Откройте `PROTOTYPE-elving.html` в Chrome. Страница работает без сети и показывает одну сетку с читаемым примером логотипа, без детали и через настоящий CAD. Измените поворот детали, ракурс глазка или угол задней подсветки. Выключите эльвинг, оба изображения совпадут. Неподвижный кадр не обновляется сам.

Пересоберите страницу из исходных модулей:

```sh
python3 prototypes/PROTOTYPE-realism/elving/build.py
```

Для локального просмотра запустите `python3 prototypes/PROTOTYPE-realism/elving/preview.py` и откройте `http://127.0.0.1:3039/PROTOTYPE-elving.html`. Завершите сервер после просмотра.

Воспроизведите проверки из корня проекта:

```sh
node prototypes/PROTOTYPE-realism/elving/evidence/check.mjs
node prototypes/PROTOTYPE-realism/elving/evidence/browser.mjs
```

Браузерная проверка использует установленный Chrome, временный профиль и CDP 9349. Она сама запускает и останавливает сервер 3039 и Chrome. Результаты находятся в [checks.json](evidence/checks.json) и [browser.json](evidence/browser.json). Сохранены фронтальное сравнение, другая лампа, повёрнутая деталь, отключённая деталь и мобильная раскладка.

Контроль использует все 20 932 треугольника из `PROTOTYPE-optics/assets/cad.json`, экспорт исходного `glazok - elving.step`. Проверка подтверждает замкнутость, наружную ориентацию, объём и размеры STEP. Верхняя плоскость z = −0,5 мм покрывает только центральную площадку, верхняя фаска тоже участвует в преломлении. Проверенная выборка прямых лучей даёт местную толщину 7,781–17,142 мм. Это диапазон выборки, не экстремумы всей детали.

Страница является геометрическим контролем. IOR 1,5 и коэффициенты поглощения предполагаются, каустики и многократные внешние отражения отсутствуют. Лампа на z = −46 мм меняет освещённость тестовой сетки на z = −28 мм. Переднее окружение даёт постоянное локальное приближённое отражение. Лучи с более чем четырьмя внутренними отражениями и лучи, не попавшие на конечную тестовую плоскость, показаны тёмными. Скользящие выходящие лучи фаски могут попадать далеко за пределы логотипа. Это не синусоидальное искажение и не ограниченная карта высот.

CPU строит поле для неизменных входящих лучей при изменении ракурса или позы CAD. Изменение лампы, картинки и поглощения использует готовое поле. В параллельном запуске поле 256 × 256 построилось за 1 519 мс, первый полный кадр занял 1 632 мс. Повторная выборка готового поля после перемещения лампы заняла 115 мс. Раздельные результаты находятся в `browser.json`. Эти замеры не проверяют бюджет 33 мс и не оценивают будущий GPU-проход.

Настоящий глазок находится в CAD на z = 195…208 мм, стекло на 192…195 мм, зеркальная призма на 12…192 мм. Осколки располагаются между эльвингом и диском, z = −0,5…10 мм. Поэтому луч идёт от +z через осколки к эльвингу, затем к подсветке на −z. Стенд без насыпки сокращает путь глазка до +45 мм. Полный CAD-порядок проверяется `assembly.mjs` и геометрическим тестом.

Для задачи 05 правильный порядок композиции: оптика осколков, затем `CADOpticalSolid.trace` выходящего из них луча. Движение преломляющих осколков меняет входящие в CAD лучи и требует изменения `rayKey`. Фиксированный эльвинг сам по себе не делает такое поле точным при движении насыпки. Быстрый заранее рассчитанный фон эльвинга сохраняет один ракурс и является угловым приближением. Контракт находится в [API.md](API.md).

Фиксированная база коррекции задачи 03: `0d51e61579e1a49aff5c4811ab2ce1b48c712ed6`. Общие модули физики, предыдущие стенды и сборка не изменены.

Проверка `hdri-browser.json` подтверждает изменение фона и отражений при неподвижных осколках, bloom, нулевое излучение в темноте, независимое вращение HDRI и остановку после него. Полная сцена с движущейся HDRI, физикой, bloom и призмой дала p95 7,3 мс на M1 после прогрева.
